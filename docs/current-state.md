## 2. Confirmed Project Direction

The project is a new business management system intended to integrate
sales, distribution, inventory, purchasing, customer credit,
collections, accounting, access control, auditability, and reporting.

The system should be professional, maintainable, secure, affordable to
operate, and portable between compatible hosting environments.

## 3. Approved Technology Direction

-   Frontend: Next.js + TypeScript.
-   Backend: NestJS + Node.js + TypeScript.
-   Backend module system: CommonJS (CJS).
-   Database: PostgreSQL on the project's VPS.
-   Database ORM and migrations: Prisma, provisionally; validate before
    adopting it for production data.
-   UI styling: Tailwind CSS.
-   UI components: shadcn/ui.
-   Service orchestration: Docker Compose, deferred during initial local
    setup.
-   Initial hosting: one VPS.
-   Public application access: HTTPS.
-   Initial mobile strategy: responsive web application and PWA
    evaluation.
-   Source control: Git.
-   Remote repository:
    `https://github.com/MohammedDotNet/asl-business.git`.
-   Default branch: `main`.
-   Package manager: npm.
-   Workspace configuration: npm Workspaces in a single monorepo.

## 5. Development Workflow

The project uses an approval-based AI-assisted workflow:

1.  Define and approve requirements.
2.  Prepare a plan without changing code.
3.  Review the plan and expected files.
4.  Approve a small implementation task.
5.  Implement the task.
6.  Run relevant tests and checks.
7.  Explain the changes and technical concepts.
8.  Review and verify the result.
9.  Commit the approved work.
10. Proceed to the next task only after review.

The coding agent is expected to work within the user's development
workflow. Its exact identity and configuration have not been confirmed.

No commit, push, or deployment should be performed without the required
approval. The project owner retains final authority over business and
architectural decisions.
